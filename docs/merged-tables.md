# PDF 合併儲存格與內容保留

原生 PDF 表格改由實際 cell bounding box 建立欄列網格。只有實體儲存格跨越多個欄／列區間時才輸出 colspan／rowspan；缺少 cell 不自動推測為合併。

一般表格維持 Markdown 管線表格，首列按欄名輸出並提醒檢查。合併表格輸出 HTML table，使用 td，不擅自判定哪些合併列是標題。文字先跳脫 HTML；換行用 br 保留。

## 保留內容的規則

- 依字元中心點分配儲存格，與鎖定版 pdfplumber 的範圍判斷相容。
- 只有已寫入表格的字元才從頁面正文排除，不按整個外框刪字，避免遺漏外框內的空缺區註記。
- 表格前後正文按頁面垂直位置排列，並保留頁碼與品質提醒。
- 重疊、反向／非有限座標、過大網格等不明情況，保留原生文字並告知表格結構未還原，不輸出假定合併。
- 最多 10,000 個實體 cell、100,000 個網格位置；字元依網格查找，不對每個字元掃描全部儲存格。每個處理階段包含取消 checkpoint。

## 驗證範圍

程式生成 PDF 驗證同表同時 rowspan／colspan、文字出現一次、前後說明順序、特殊字元、缺 cell 區域註記，以及不明幾何回退。打包程式也須以真正執行檔轉換合併表格並檢查 span 與內容。

無框線及稀疏表格另有獨立推測與測試路徑，見 [無框線表格](borderless-tables.md)。尚未驗證跨頁續表自動合併、任意多欄中混排表格、旋轉表格或掃描表格的結構辨識。合併表格輸出不代表這些功能完成。HTML 顯示依閱讀器支援程度不同；原始 Markdown 仍保留標記與內容。

原里程碑 3 的「OCR、版面與表格引擎」拆為「OCR 與合併表格基線」及「複雜版面、跨頁／無框線表格驗收」。後者現以 [驗收矩陣](layout-acceptance.md) 記錄 Linux 代表性案例、嚴格結構斷言及打包程式證據；其完成不等於任意版面或 Windows 已通過。
