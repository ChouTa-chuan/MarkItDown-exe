# 原生文字型 PDF 無框線表格

精準模式新增保守的文字對齊推測，不使用此路徑辨識掃描表格，也不代表已有完整深度版面模型。

## 可接受的基線

- 至少三列（文字型首列與兩列資料），兩至八欄。
- 各欄左緣或右緣穩定，列距規則且互不重疊。
- 至少一個資料欄大部分是可辨識數值；僅含文章敘述、首列全為數字或欄位漂移者不強制轉表格。
- 稀疏路徑要求三至八個明確文字欄名、至少兩列資料，至少兩欄有數值證據；以表頭水平位置分配詞，缺格保留空白，不把上一列 SKU 或數字向下填入。
- 文字間距依字高在 8–18pt 間調整，以保留較窄的欄名間距；每欄仍須有穩定左緣或右緣、規則且不重疊的資料列。
- 以 Markdown 輸出，標記 inferred-borderless-table，提醒首列與欄列屬推測，需核對。

推測器也可處理已有框線表格後的剩餘文字，同頁兩種類型不互相吞掉。只排除已輸出的字元，保留前後正文，特殊字元跳脫。

## 資源與限制

超過 20,000 詞時跳過後續表格／雙欄對齊推測，保留原生文字。稀疏候選每次最多檢查 256 列，全頁最多 100,000 次詞比對；超量未確認區域仍保留文字。這是分析階段上限，不是整個 PDF 解析器的 RAM 硬上限。正常路徑重用同一份詞座標，避免重複提取。分析包含取消 checkpoint。

全為文字的表格、缺少明確表頭、每列僅一格、複雜換行、旋轉及掃描表格尚未完整支援。符合條件的相鄰頁可提示續表，但不自動合併。對齊不等於表格；不明確案例不強制建立欄位。純數值首列也不擅自當作標題。

## 上游稀疏表格驗收

補驗 Microsoft MarkItDown 固定提交的 SPARSE-2024-INV-1234_borderless_table.pdf，來源與 SHA-256 位於 tests/fixtures/UPSTREAM.json，原 MIT 授權保留。

此上游測試報表包含缺格與錯落列。其單欄外框內其實有多欄文字；先排除錯誤單欄化，再以表頭定位六欄。第一頁八列、第二頁十列均逐格比對（含空格、金額、日期及狀態），另核對兩頁共 1,397 個正規化英數字元無遺漏／重複。原結構 expectedFailure 已改為正式通過的回歸測試。

這是上游公共測試資料，不是實際使用者文件。字元檢查排除空白與標點，不能單獨證明結構或閱讀順序；本例另有完整欄列斷言。原 ONNX 繁體品質缺口仍存在，並在進度頁揭露。圖表視覺與標誌未重建。

## 證據

測試涵蓋兩欄／三欄數值、右對齊數字、有框線與無框線同頁、前後正文、雙欄文章、數字首列、漂移欄位、稀疏純文字反例、上限與取消，以及上游樣本逐格驗收。[驗收矩陣](layout-acceptance.md) 記錄範圍、重跑方式及剩餘限制。
