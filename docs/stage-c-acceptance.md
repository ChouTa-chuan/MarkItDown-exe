# 大階段 C 驗收表

使用 B3 CPU 重新定版後的新安裝包。在乾淨的 Windows 10 x64 和 Windows 11 x64 各填一份。先做 C1 及 C2-1 至 C2-5，再做 C3，最後修復與移除。安裝包從可信來源取得後，先在 PowerShell 執行 `certutil -hashfile ".\安裝程式.exe" SHA256`，核對發佈資訊，再把實測 SHA 填在下方。兩次執行各自記錄 SHA。安裝或測試時使用合成或公開樣本。

| 驗收資訊 | 實際值 |
| --- | --- |
| B3 後版本與來源提交 | 待填 |
| 安裝包檔名及來源連結 | 待填 |
| **安裝包 SHA-256** | **待填** |
| Windows 版本、組建及架構 | 待填（執行 `winver`） |
| 測試環境及乾淨快照識別碼 | 待填 |
| 驗收人、日期、時區 | 待填 |
| RAM 容量 | 待填 |

每列先做「操作」，達到「預期結果」且附件保存後，再把該列的 `[ ]` 改為 `[x]`。失敗、阻擋或尚未執行的列保持未勾，旁邊記錄實際結果、重現步驟與附件。遇到缺失後使用新安裝包重驗時，另填一份對應新 SHA 的紀錄。Windows CI 的紀錄可供參考，C 節需保存乾淨機與人工操作證據。

## 填寫後保存

在 `docs/development-records/runs/stage-c-YYYY-MM-DD-主題/` 為每個 Windows 環境保存一份完成表 `README.md`，並加上 `manifest.json`，記錄驗收日期、來源提交、安裝包 SHA-256、各項結果和附件 SHA-256。相對路徑指向同一目錄內的附件，或在 README 引用存放大型附件的可追溯位置與雜湊。截圖及日誌發布前移除個資，保留判讀所需欄位。由負責驗收的人確認每列結果後，再依專案流程處理 `base-clean-machine-manual`。
