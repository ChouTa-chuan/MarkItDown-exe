## 操作與狀態

從主視窗按「選配元件管理」。列表顯示元件名稱／版本、必要或選配、下載與解壓容量、授權、觀察狀態、目前啟用／前一版本；下方顯示來源、平台、能力、RAM／VRAM／磁碟估算及原因。

| 操作 | 行為與界限 |
| --- | --- |
| 重新讀取本機狀態 | 不連網、不執行健康推論；過去 ready 顯示「上次健康通過（使用前重驗）」 |
| 匯入簽章目錄 | 限大小受限的一般檔案，拒絕連結／FIFO；必須由應用程式固定信任根核准，不匯入使用者提供的金鑰 |
| 更新線上目錄 | 只按明確按鈕才連線到可信程式配置的固定 URL；沿用 C05 簽章、版次、到期與來源限制 |
| 下載並安裝 | C05 可恢復下載／快取 → SHA-256 → C06 staging、健康與交易啟用；不逐檔詢問 |
| 匯入包檔並安裝 | 只接受目前核准描述對應的 ZIP／archive，使用原有離線驗證與交易流程 |
| 重新檢查健康 | 重新驗檔及真實可信探針，保持 active 不變；取消須保留取消狀態 |
| 修復／啟用／回復 | 使用 C06 的所有權、鎖、相容性、反向依賴及真實健康檢查；不強制切換不相容版本 |
| 查看授權原文 | 在共享維護鎖下核對授權檔大小／SHA-256，再以純文字顯示前 256 KiB；完整原文隨包保存 |
| 移除 | 需一次確認；必要元件不提供移除，後端仍檢查依賴、未知／改動資料與使用中鎖 |
| 恢復未完成維護 | 明確呼叫既有交易恢復，不擅自刪除來源不明資料 |

到期或撤回的目錄不授予執行／安裝／修復權；仍列出已受管舊版本，以便查看經核對的授權或安全移除。相同版本目錄不同內容、已見版次倒退及未知來源仍由 C05 拒絕；此處沿用 C05 的目前程序版次記憶與有效快取重驗，未宣稱增加抗本機磁碟回滾的永久信任儲存。

**目前未發布正式元件目錄及發行金鑰。** 一般桌面的預設服務沒有信任來源，會清楚顯示「正式選配元件目錄尚未提供」，停用目錄匯入／更新與未核准安裝；不內建測試金鑰，也不讓使用者輸入任意來源繞過驗證。既有基本轉換、OCR 設定及舊模型管理繼續使用。測試將短效的臨時信任政策注入相同程式路徑，私鑰只在記憶體，這不等於正式服務已上線。

## 模組責任與背景流程

| 模組 | 責任 |
| --- | --- |
| `component_dialog.py` | 元件列表、明細、動作與取消、進度、純文字授權及關閉保護 |
| `ManagementThread` | QThread 背景呼叫服務；狀態／結果回 Qt 主執行緒，下載進度最多約每 0.1 秒一次，避免事件佇列堆積 |
| `components/management.py` | 固定 `TrustedSource`、有界目錄快取、主機版本、動作調度、狀態摘要與錯誤隔離 |
| `components/lifecycle.py` | 新增 `check_health()`，用共享維護鎖重驗指定版本，保持 active 不變 |
| `component_workers/binding.py` | 將原生 worker 取消傳回 `Cancelled`，避免能力解析把取消誤記為不健康 |
| `desktop.py` | 主視窗入口、目前資源設定、批次時停用管理入口、父視窗關閉保護 |
| `packaging/desktop.spec` | 帶入專案 metadata，讓打包後可取得實際主程式版本；本輪未重建主程式或 Windows 安裝包 |

檔案、網路、雜湊與原生健康檢查都在背景。每個操作使用自己的取消事件，同一資料根以核心管理鎖互斥；實際元件維護仍由 C06／C07 的租約／guard 保護。列表在共享維護鎖下讀取，失敗／取消後重新讀真實登錄，不以樂觀 UI 宣告成功。

操作中停用重複動作並保留取消。Esc、關閉管理視窗或父視窗都先要求取消，等待背景程序與交易收尾，沒有使用 `QThread.terminate()`。單次網路讀取仍受既有 10 秒等待界限；RAM 為軟性預算，原生呼叫透過 C07 取消／逾時邊界處理。

按鈕是使用者對當次操作的明確要求，不改寫設定 v6 的偏好、OCR 後端或自動下載欄位。元件啟用不會改變現有文件的 OCR 選擇；程式 0.8.0 已由 [C10](managed-conversion.md)接上精準 PDF，須明確選擇受管 CPU 後端；原生／空白頁不要求 OCR 元件。C08 不建立帳號、外掛商店、常駐服務或顯卡驅動安裝功能。
