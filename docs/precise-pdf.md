# PDF 精準流程

精準模式逐頁依原生文字、影像覆蓋及解碼異常，自動選擇原生解析、OCR 或空白頁。純原生短標題不強制 OCR，混合內容有提醒；快速模式仍走 MarkItDown 基線。

原生頁支援有框線表格並排除重複文字，簡單雙欄以中央留白啟發式按左再右排序。跨欄標題、跨頁／合併表格及學習式版面模型未完成。

OCR 使用本機 Tesseract，優先 chi_tra+eng，缺少繁中模型時提醒。PDFium 渲染上限 1,200 萬像素，使用灰階與字高正規化。文字不足最多以 200／300 DPI 嘗試兩輪，實際 DPI 受像素上限限制；每輪 90 秒逾時，OpenMP 限一執行緒。

每頁保留頁碼、路由及提醒。缺少引擎時明確失敗；OCR 無結果保留可見提醒，不視為辨識成功。取消停止 OCR 子程序並清理本次暫存。

## 模型

先從可信來源安裝 Tesseract 5，再執行：

```bash
python scripts/fetch_ocr_models.py /path/to/tessdata
```

下載約 6.4 MB 官方固定版本繁中／英文模型與 Apache-2.0 授權，使用 HTTPS 與固定 SHA-256 驗證；既有錯誤檔不靜默覆寫。將 TESSDATA_PREFIX 設為該目錄。尚無應用內下載／移除 UI，Windows 包也尚未包含 OCR 原生元件。

## 驗證範圍

以程式產生的英／繁中掃描、混合 PDF、表格與雙欄，檢查路由、內容、無重複、提醒、有界重試及取消。掃描案例與原生 MarkItDown 比較，只證明該樣本增加辨識內容，不代表整體準確率。

測試發現過大字形會漏行或誤判，因而加入字高正規化；仍需真實低品質、旋轉、混排與多種字級評測。自動旋轉、任意區域 OCR、深度版面模型、圖片擷取及 GPU 未完成。

逐頁提供 checkpoint，但原生單頁函式及正在執行的 OCR 不能因 permit 清除立即釋放記憶體；RAM 仍是軟性預算。
