# 雙引擎交叉核對

桌面 OCR 後端新增「雙引擎交叉核對」，CLI 使用 --ocr-backend onnx_verify。此模式需要 ONNX 套件及本機 Tesseract；沒有自動下載或安裝原生執行檔。比單引擎慢，且不保證兩者一致就是正確。

## 輸出規則

- 同一頁分別辨識，Tesseract 原始文字為主要結果，ONNX 為候選。
- 只忽略空白比較，不將簡體字轉繁體、不修正數字或否定詞、不自行補字。
- 不一致時顯示品質提醒，將兩份原文保留在 Markdown 的 details/pre 區塊；HTML 特殊字元會跳脫。
- 至少一個結果為空時標示核對未完成，不把空字串一致視為成功。
- 文字一致也提醒需要核對原頁；跨引擎一致不是正確性證明。
- 長頁超過 10,000 字元時不逐區對齊，保留全文與不一致提醒，避免反覆字串造成高耗時。

主要結果不會因候選較長或分數較高而靜默替換。沒有用字典針對樣本修字。原 ONNX 繁體品質缺口仍保留為預期失敗，不因核對模式使用另一引擎而宣稱已修好。

## 流程與資源

同一頁仍最多兩種解析度嘗試；每輪可能執行 ONNX 與 Tesseract 各一次。引擎間會通過資源 checkpoint，可取消，缺少任何必要引擎會明確失敗並清理本次輸出。模型推論期間的即時暫停與 RAM 硬限制尚未完成。

設定 schema v5 支援此後端，讀取 v1–v4 並保留原先引擎選擇。預設仍為 Tesseract；新增功能不自動切換使用者設定。

## 四份合成樣本

ocr-quality-sample.json 現含會議文字、金額／日期、否定句、英文四份原文與各引擎輸出。比較以忽略空白後的字元編輯距離計算，不評估段落或英文空格結構，也不能代表真實文件準確率。

會議樣本：ONNX 有 2 個差異，Tesseract 0；金額／日期樣本：兩者各有 1 個差異；否定句：兩者 0；英文：ONNX 1、Tesseract 0。核對偵測到三份樣本的引擎分歧，但沒有因此自動選出正確全文。金額樣本說明主要引擎也可能出錯。

仍需真實掃描、旋轉、低對比、複雜版面及表格的品質驗收。
