# C02：舊模型轉接與設定遷移

程式 **0.2.1**，架構 **0.4**，2026-11-06（台北）。[本輪驗收紀錄](development-records/runs/c02-2026-11-06/README.md)獨立保存，不覆寫 C01 證據。

## 已接入的流程

`ModelDialog → LegacyModelsAdapter → 舊 models.py ＋ ComponentRegistry`。模型清單仍採隨包的固定提交及 SHA-256，原下載器的官方來源、16 MiB 上限、取消、快取重用及損毀拒絕覆寫繼續沿用。

| 來源 | 操作方式 | 所有權規則 |
| --- | --- | --- |
| 明確指定的外部／自備路徑 | 只讀核對、保存引用；轉換仍傳遞原路徑 | 不搬移、覆寫或刪除 |
| 舊預設 `models/tesseract` | 模型管理優先顯示既有目錄，按只讀引用處理 | 不因位於程式資料目錄就接管 |
| 新 `models/tesseract-managed` | 明確下載到空目錄時建立受管收據，沿用原下載器 | 收據須符合目錄及固定清單；已有未知資料時拒絕接管 |

開啟模型視窗不會下載或切換設定。只讀視窗可按「開啟程式專用模型下載目錄」，再明確按「下載／驗證並使用受管模型」；成功後填入新路徑，另按儲存才持久化。既有／外部模型不能由視窗直接移除；受管目錄也只移除固定清單內未修改的檔案，未知檔案與收據保留。

`LegacyModelsAdapter.observe()` 回傳不可變的逐檔觀察、模型資料是否完整、收據判斷及引用 ID。每次重新檢查實檔，不從資料庫的舊狀態決定可用。**模型完整不等於 OCR 引擎 ready**；本 adapter 的 `engine_ready` 固定為 false，沒有繞過 C01 的引擎健康檢查。

明確 OCR 執行檔／模型路徑繼續優先。失效時在需要 OCR 的步驟顯示失敗，不悄悄改用 PATH／環境模型或另一個引擎；純文字與不需 OCR 的原生轉換不因此被阻擋。受管基本引擎的自動選擇尚待 C03／C10。

## 設定 v6

讀取 v1–v5 僅在記憶體轉成 v6，原檔保持不變。保留 RAM、保留量、等待時間、CPU／GPU 配置、OCR 後端與原始路徑文字；不正規化、檢查所有權後搬移或下載模型。

| 新增欄位 | 預設與用途 |
| --- | --- |
| `quality` | `precise`；保存快速／精準選擇，CLI 明確 `--quality` 優先 |
| `onboarding_version` | `0`；保留首次精靈完成版本，精靈本體待 C09 |
| `component_preferences` | 空清單；能力、指定元件與可選穩定版本，不能包含健康或安裝狀態 |
| `update_channel` | `stable`；目前只保存偏好，不啟動更新服務 |
| `allow_optional_downloads` | `false`；目前只保存選配下載意願，不啟動背景下載；舊模型的每次手動下載仍由按鈕明確發起 |

桌面以已載入的完整設定為底修改控制項，因此沒有顯示在 GUI 的新欄位不會因儲存 RAM 而歸零。CLI 也沿用完整設定並套用明確參數。未知欄位、重複 JSON 欄位、不合法資料、未來 schema 與超過 64 KiB 的檔案均拒絕，不以預設值覆蓋。

明確儲存舊設定時，先以原始位元組保存 `settings.json.pre-v<舊版>-<內容雜湊前16碼>.bak`，再以同目錄暫存檔原子替換。備份不覆寫；既有同名備份須內容相同才重用。備份或替換失敗保留原設定，明顯並行變更也會拒絕寫入。這是單檔保護，不宣稱已有跨程序設定編輯鎖。

## 登錄 schema 2

原 `components` 表及資料保持不變；新增 `model_references` 表，記錄路徑衍生 ID、來源類型、可信固定清單雜湊、逐檔觀察與時間。`origin=managed` 只是上次觀察，不能單獨授予刪除權；adapter 仍需檢查專用路徑與收據。

從 schema 1 升級前，以 SQLite backup API 保存一致性快照 `component-registry.pre-v1-<雜湊前16碼>.sqlite3`，不直接複製可能有進行中交易的資料庫。新增表與 `user_version=2` 在同一交易完成；失敗回復原版本與資料。不支援的 schema、資料表或欄位仍拒絕，不自動清空。

要回到程式 0.2.0 或更舊版本時，先另外保留目前 v6 設定、schema 2 登錄及其備份，再使用對應舊快照；舊程式不能直接讀取新 schema。C02 不提供自動降版、刪除新資料或通用安裝回復介面。

## 驗收與後續

驗收涵蓋 v1–v5 值保留／備份、故障注入、資料庫升級回復、外部資料保留、受管下載／重用／取消、原桌面文字轉換、CLI 路徑傳遞、真實固定模型的只讀核對，以及明確失效 OCR 路徑不得回退。

在已安裝完整開發依賴、Tesseract 與固定繁中／英文模型的環境執行：

```bash
TESSDATA_PREFIX=<verified model directory> QT_QPA_PLATFORM=offscreen python scripts/check_component_acceptance.py --check C02 --report /tmp/c02-acceptance.json
```

跳過不列為驗收通過。Windows／GPU 尚未實機驗證；收據是避免誤接管的本機紀錄，不是防止同帳號惡意改檔的簽章。C05 可信目錄／續傳、C06 通用交易安裝／使用中鎖／修復、C08 完整元件管理頁、C09 精靈及 C10 自動能力路由仍有各自檢核。
