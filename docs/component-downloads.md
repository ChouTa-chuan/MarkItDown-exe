## 信任政策與簽章

信任根只能由應用程式的 `TrustPolicy` 提供，包含政策版本、目錄 ID、最低目錄版次、Ed25519 公鑰、撤銷 ID、核准 HTTPS origin 及容量上限。網路封套不能新增公鑰，也不能放寬來源或資源限制。輪替須透過新版受信任政策加入公鑰；撤銷優先於公鑰存在。

目錄格式為 `{"payload": {...}, "signature": {"key_id": "...", "algorithm": "ed25519", "value": "base64..."}}`。簽署 payload 的 UTF-8 JSON，排序鍵、無空白、禁止 NaN；payload 欄位固定如下：

| 欄位 | 條件 |
| --- | --- |
| `schema_version` | 嚴格整數 `1` |
| `catalog_id`／`trust_policy_version` | 必須與應用程式固定政策相同 |
| `revision` | 不低於政策最低版次與本 verifier 已見最高版次；同版次不得換內容 |
| `issued_at`／`expires_at` | UTC `YYYY-MM-DDTHH:MM:SSZ`；拒絕過期、無效或超過五分鐘容差的未來目錄 |
| `components` | 1–256 份 C01 描述，ID／版本不重複，來源與大小須符合政策 |

目錄總量最多 1 MiB，重複／未知／缺漏欄位與不合法巢狀結構均拒絕。元件描述中的個別簽章欄位仍只保存資料；來源由整份目錄的真實 Ed25519 驗證確認，涵蓋完整描述內容。即使傳入自行建立的 `VerifiedCatalog`，服務也會重驗原始封套，不使用被替換的物件欄位。

目前沒有發布正式元件目錄或預裝發行金鑰。本輪實際 HTTPS 驗收使用一次性記憶體測試金鑰簽署固定官方授權檔的描述；私鑰不寫入專案，也不作為未來產品信任根。跨程序／重新啟動的防回退下限由可信政策 `minimum_revision` 決定；已見最高版次目前只保存在 verifier 實例內，沒有宣稱跨重啟高水位已持久化。

## 下載與續傳

1. 每次動作先驗目錄，再查找明確的元件 ID／版本，不能傳任意下載 URL 取代目錄。
2. 檢查受管快取路徑、磁碟空間並取得單包檔鎖；已有完整快取須重驗大小／SHA-256。
3. HTTPS 請求最多三次，建構時可設 1–5 次；每次 timeout 10 秒，重試等待可取消，最多四秒。只有暫時性網路錯誤、408／429／指定 5xx 等使用剩餘額度；403／404、磁碟錯誤、取消與資源 checkpoint 失敗不重試。
4. 使用 64 KiB 固定緩衝與宣告大小上限，不把整個包檔載入記憶體；保留預設 64 MiB 磁碟空間。政策預設包檔上限 4 GiB、宣告展開上限 64 GiB；本服務不解壓。
5. 完整接收後重驗檔案與目前信任狀態，拒絕傳輸期間過期／撤銷的目錄，再排他發布完整快取並登錄 `verified`。下載不會產生 `installed` 或 `ready`。

| 情況 | 行為 |
| --- | --- |
| 部分檔＋相符強 ETag | 發送 `Range` 與 `If-Range`；206 的範圍、總長度及 ETag 全部吻合才附加 |
| 無 ETag／弱 ETag／壞續傳 metadata | 清除該受管片段後重新完整下載 |
| Range 得到 200 | 視為完整新回應，從零寫入，不把資料重複附加 |
| 206 範圍／ETag 不符或 416 | 捨棄舊片段，使用剩餘額度重新請求 |
| 回應太短／暫時斷線 | 保留可驗證片段，在額度內續傳或重來 |
| 長度超限或最終 SHA-256 不符 | 不發布完整檔；拒絕損毀內容 |
| 取消 | 保留受管片段，下一次明確操作才續做，不標示可用 |

來源與每次重新導向均只允許核准的 HTTPS origin、預設 443 埠，不接受帳密、HTTP 降級或本機協定。跨 origin 的核准重新導向清除舊 Range 條件，避免沿用不適用的續傳狀態。保持系統 proxy／CA，不關閉 TLS 驗證。

## 快取、離線匯入與登錄

快取使用包檔 SHA-256 衍生的 `.archive`、`.part`、`.resume.json`、`.lock` 名稱。拒絕符號連結／reparse point 與非一般檔案，保留未知檔案；已有完整檔損毀時拒絕使用，不靜默覆寫。鎖避免同一包檔同時寫入；崩潰留下的鎖不自動刪除，後續維護／崩潰恢復與總快取配額屬 C06。

`import_offline()` 仍需有效簽章目錄，先驗來源大小／SHA-256，再限量複製與重驗後發布；不搬移或刪除使用者提供的原檔。離線不代表可略過到期、撤銷或相容性檢查。C01 登錄只接受已驗證結果，既有已安裝紀錄不因重新取得快取而被降為下載中；C01 能力解析仍須另外核對安裝、版本／依賴與健康探針。
