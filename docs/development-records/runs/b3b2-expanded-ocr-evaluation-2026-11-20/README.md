# B3b2 擴大三語識別樣本

在這組樣本上，v5 mobile 和 v6 small 的繁中字元正確率均為 **98.52%**，現行 v4 為 **86.23%**。簡中三份樣本逐份比較，v5 有一份少 1 個編輯錯誤，其餘持平；v6 逐份持平。v5 在三語合計的編輯錯誤較少，模型也比 v6 小 4,603,077 bytes。以下結果供選型，正式產品維持現行 v4。

## 樣本與評分

繁中、簡中、英文各有三份自製合成圖。每種語言包含襯線內文、四欄表格、含標題和小字的公告。每張圖皆有 17–20 px 的小字，內文為 28 px，表格格內為 22 px。固定 PNG 合計 323,739 bytes。每份的參考稿、生成方式、字型版本指紋及圖片 SHA-256 可回查，圖片也已由同一腳本重繪並做位元組比對。[樣本與來源](samples.json) · [重繪程式](render_samples.py)

沿用 B3b 的 `normalized()`、`edit_distance()` 與 `measure()`。字元用 NFC，忽略空白，保留大小寫、標點及簡繁字形。表格的參考順序為逐列由左至右。每張圖以 OCR 讀取順序計算編輯距離，所以漏字、誤讀、誤加文字及順序差異都會影響分數。分語言合計使用總編輯距離除以總參考字數，正確率為 `max(0, 1 − 錯誤率)`。[B3b 評估器](../b3b-ppocr-model-review-2026-11-20/evaluate.py)

使用 Linux x86-64、Python 3.12.14、RapidOCR-ONNXRuntime 1.4.4、ONNX Runtime 1.31.1，CPU 推論各階段皆為單執行緒。偵測器、方向分類器、現行識別器與設定先驗證 B3b 固定 SHA-256，四組只更換評估用的識別權重。繁中 v3 是 B3b 已驗證的 UmiOCR 封存版，用於比較是否有理由另設繁中選項。四份權重的完整 SHA-256 和套件版本見結果檔。[模型來源與指紋](../b3b-ppocr-model-review-2026-11-20/evaluation-inputs.json) · [原始結果](evaluation-results.json)

在這組樣本上，v5 與 v6 繁中同為 7 個編輯錯誤，但分布不同。v5 的繁中內文零錯誤，v6 在繁中表格與標題各少 1 個錯誤。v5 英文三份皆零錯誤，v6 英文內文有 1 個錯誤。繁中 v3 的繁中分數高於 v4，但低於兩個通用候選，簡中與英文分數也低於 v4。測量涵蓋三種合成版面，未比較真實掃描的噪點、手寫、混排、Windows 封裝或推論效能。

## 選型方案

1. **優先評估以 v5 mobile 作為單一識別模型**。在這組樣本上，繁中與 v6 同分，簡中與英文略高，檔案也較小。
2. **選 v6 small**。若應用以繁中表格或標題為主，這兩張樣本的結果略占優勢，可用更貼近實際用途的資料複驗差異。
3. **維持 v4**。可保留現有選型，繼續沿用既有的繁中品質揭露。專用 v3 若考慮採用，僅適合在使用者明確選擇繁中時另開選項，在這組樣本上優先度低於兩個通用候選。

任何候選的實際採用另由使用者決定。

## 離線重跑

先在 repo 外的模型目錄準備 B3b 指定檔名的 v5、v6 及繁中 v3，v4 由已安裝的 B3b 固定 wheel 提供。執行器驗證套件、模型與圖片指紋後才開始比對。重繪用的字型相對於 `/usr/share/fonts`，若目錄不同可用 `--font-dir` 指定。

```bash
B3B2_DIR=docs/development-records/runs/b3b2-expanded-ocr-evaluation-2026-11-20
python -B "$B3B2_DIR/render_samples.py" --output-dir /tmp/ppocr-b3b2-samples
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python -B "$B3B2_DIR/run_evaluation.py" \
  --models /tmp/ppocr-models --output /tmp/ppocr-b3b2-results.json
```

重跑的辨識 JSON 與已保存結果逐 byte 一致。Linux 混合與逐模組完整回歸均通過，現行產品測試仍記錄 v4 的繁中品質已知缺口。模型只在本機暫存區使用，PR 只跑歷史索引檢查。[專案回歸進度](../../../progress.json)
