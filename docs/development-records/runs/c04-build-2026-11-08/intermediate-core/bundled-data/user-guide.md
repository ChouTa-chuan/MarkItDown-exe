# MarkItDown 桌面版使用說明

適用開發預覽版。Windows 安裝包、實機顯卡及正式發佈仍待驗收；這份手冊不代表已提供可安裝的 Windows 正式版。

## 首次設定與 RAM 建議

第一次啟動會離線檢查本機基本 CPU 引擎，顯示 RAM 建議及繁中／英文合成健康結果，不會下載模型、選配或更新。新使用者預設採用自動 RAM 預算及系統保留量；既有設定預設保留，也不改動明確路徑、OCR 後端、品質或 GPU 偏好。

按「完成設定，略過選配」才儲存；完成後不會在每次開啟重複提示，可從「首次設定／重新檢查」手動再開。按「稍後再設定」不寫入完成標記，等待背景檢查停止後關閉。

找不到引擎或模型時會明確顯示 OCR 尚未就緒，仍可完成流程並使用基本文字轉換。完成標記只表示首次設定流程已完成，不代表 OCR 永久可用或產品已內含原生引擎；目前 Windows 基本引擎打包仍在開發中。RAM 是軟性預算，無法保證其他作業完全不受影響。

## 開始轉換

1. 開啟桌面預覽程式，按「新增檔案／拖放」，或把文件拖到視窗。
2. 按「輸出資料夾」選擇目的地。程式不會覆寫既有檔案；重複名稱的檔案會顯示失敗原因，其他文件可繼續。
3. 選擇轉換模式及 OCR 後端，確認 RAM／CPU 設定。
4. 按「開始轉換」。清單顯示排隊、處理中、等待資源、完成、失敗或已取消。
5. 右下方預覽最後完成的文件；也可到輸出資料夾用 Markdown 編輯器開啟。

輸出名稱保留原副檔名再加 .md，例如 報告.pdf → 報告.pdf.md。從不同資料夾加入同名文件時，請分開輸出，避免名稱衝突。來源文件不會被覆寫。

支援的開發基線：UTF-8 txt/md、DOCX、PPTX、XLSX、HTML/HTM、文字型 PDF。掃描 PDF 需要相應 OCR 引擎。密碼保護、損壞、不支援格式或引擎缺失會顯示錯誤。

## 快速與精準

- 快速：以原生 MarkItDown 解析，適合一般 Office 與可選取文字的 PDF。
- 精準：PDF 自動逐頁判斷文字、掃描、混合內容及空白頁，按需要執行 OCR 與表格／閱讀順序分析；不用手動指定每頁處理工具。

精準不保證完整重現排版。圖表、公式、複雜跨頁／無框線表格與低品質影像仍可能需要人工核對。頁碼及品質提醒會寫進結果，請優先檢查有提醒的頁面。

## OCR 後端

### Tesseract（預設）

需本機 Tesseract 執行檔。可用「選擇引擎」指定路徑；留空時自動尋找。Windows 開發包目前未自動提供此原生元件。

按「模型管理」可查看繁體中文／英文模型的來源、版本及授權。舊版或自備目錄以只讀方式核對並記錄，不搬移，也不提供直接下載或移除原資料。

需要下載時，按「開啟程式專用模型下載目錄」，再按「下載／驗證並使用受管模型」。下載約 6.4 MB，完成後填入模型路徑；開啟視窗不會自動下載或更換原設定。若程式專用目錄已有無法確認所有權的資料，會停止而不接管。

也可按「選擇目錄」使用既有模型。按「儲存資源設定」保存引擎與目錄，不需要自行設定環境變數。損毀檔案不會被靜默覆寫；僅新建且有受管紀錄的目錄可移除已驗證模型，未知檔案保留。模型檢查通過仍需另外備妥 OCR 引擎。

### ONNX OCR（實驗性）

使用隨選配套件提供的模型，不需要外部 Tesseract 執行檔。CPU 推論已驗證，但繁體字可能漏字或混用字形，尚未達到預設品質要求。請勿直接把輸出當作正確逐字稿。

### 雙引擎交叉核對

需要 Tesseract 與 ONNX。較慢，以 Tesseract 原文為主要結果；兩者不同時標記差異，保留 ONNX 候選原文，不自動補字、改數字或繁簡轉換。

結果中的「交叉核對：兩引擎原始文字」區塊可供比對。至少一個引擎沒有文字時會標示核對未完成；即使一致也不代表一定正確。

## 選配元件管理

按主視窗「選配元件管理」，可查看版本、下載／解壓容量、授權、RAM／VRAM 估算、上次健康狀態與啟用版本。開啟視窗只讀本機資料，不會自動下載。

正式選配目錄尚未提供時，畫面會停用未核准下載；基本轉換、既有 OCR 設定及「模型管理」仍可使用。目錄與發行金鑰由程式提供，不需自行設定 Python、pip 或輸入金鑰。

有受信任目錄時，可明確更新／匯入簽章目錄，再選「下載並安裝」或「匯入包檔並安裝」。完成驗證與健康檢查才啟用；也可重驗健康、修復、啟用所選版本、回復前版、查看授權原文或移除受管選配。必要元件與仍有依賴的版本不可任意移除，未知檔案保留。

大型元件在背景處理，進度與取消按鈕可繼續操作；關閉時先等待取消與維護收尾。失敗原因顯示在視窗下方，不會停用基本轉換。啟用元件不會自動改變原 OCR 後端；欲使用時明確選擇「受管 CPU OCR」。精準 PDF 只有 OCR 頁會要求元件，原生／空白頁仍直接處理。健康通過不代表任意文件準確率或繁體品質已達標。

## 受管 CPU OCR 與文件路由

在 OCR 後端選「受管 CPU OCR（選配、繁體品質未達標）」，預設元件 ID 為 onnx-cpu-ocr。版號留空使用已啟用版本；若指定版號，請先在元件管理啟用，程式不自動切換版本。預設仍是 Tesseract，原有 ONNX／雙引擎設定保留。

精準 PDF 自動逐頁判斷原生／空白／OCR，僅 OCR 頁取得元件並檢查健康；整份文件及輸出提交期間固定版本。輸出保留頁碼、路由、警示與使用的元件版號。缺元件、版本不符或失效會讓該文件失敗，可開元件管理處理，或明確另選已備妥後端後重試；不自動下載、降級或覆寫既有輸出，其他批次文件繼續。

正式選配來源尚未提供時，掃描頁不能使用未核准元件；原生／空白頁不因此要求下載。受管 CPU 不會啟用 GPU，ONNX 繁體品質仍有已知缺口。RAM 是軟性預算，等待與取消會傳到元件程序；原生處理可能須等待目前步驟停止。

## 設定升級與備份

讀取舊設定不會修改原檔。首次儲存時會保留一份含舊版本與內容識別碼的 `.bak` 備份，再更新設定；RAM、CPU、OCR 後端及自備路徑保留。轉換模式也會保存。

備份或儲存失敗會保留原設定；無法讀取或較新版的設定也不會被預設值覆蓋。要回到舊程式時，請先另外保留目前資料，再使用相容的舊設定備份；不要直接把新設定交給舊版覆寫。

## RAM 與 CPU

「自動規劃 RAM」預設採系統優先。可改成手動 MiB 預算，另設定留給 Windows 與其他程式的保留容量。預設保留 2048 MiB；電腦同時有其他大型工作時可提高保留量。

記憶體不足時程式會等待或暫停派送工作；超過等待上限會顯示失敗，可釋放記憶體或調整設定後重試。RAM 是軟性預算，第三方引擎可能瞬間超量，不能保證其他程式完全不受影響。

CPU 執行緒預設一個；提高可增加部分引擎的並行度，也可能影響其他工作。這不是整機 CPU 百分比硬上限。原生函式執行時可能需等待目前步驟結束，無法立即暫停。

## GPU

「裝置診斷」可查顯卡、驅動、顯示記憶體及候選後端。偵測成功不等於模型已能使用 GPU。目前桌面 GPU 選項停用，等待實機驗證；不要把 CPU 推論誤認為顯卡加速。

GPU 配置預算是候選 CUDA session 的配置目標，不是整張顯卡的硬上限，CPU 模式也不會因此使用 GPU。

## 表格與閱讀順序

- 一般原生表格輸出 Markdown；合併儲存格有幾何依據時輸出 HTML rowspan／colspan。
- 有框線及無框線表格在相鄰頁、欄位／表頭與頁面位置吻合時可能標示延續；仍保留各頁、重複表頭與資料，不自動合併。
- 對齊數值型無框線表格及明確表頭下的缺格列有基線支援；空格保持空白，不猜測補值。全為文字、複雜換行或幾何不明者可能保留文字並提醒。
- 有穩定中央留白的雙欄文字可依左欄再右欄讀取，跨欄標題可切分區塊。任意多欄、表格混排、圖表及掃描表格尚未完整重建。
- HTML 表格及 details 的顯示取決於閱讀器；在純文字編輯器會看到標記，內容仍保留。

來源註記如 source-page、source-table 是核對線索，不表示原始排版已完整保留。

## 取消、失敗與重新轉換

按「取消批次」會要求停止，原生步驟可能稍後才回應。關閉工作中的視窗也會先要求取消；等程序停止後再關閉。

目前未提供持久化佇列或中斷續跑。重新啟動後需重新加入檔案。已完成的輸出會保留，失敗的當次暫存通常會清理；斷電或強制終止仍可能留下暫存。

重新轉換前請改輸出資料夾，或自行保留／移走舊輸出，程式不會覆寫。程式只支援可完成排他提交的檔案系統（例如 NTFS）；不支援的目的地會失敗。

## 常見問題

- 找不到 Tesseract：指定正確的本機執行檔，或在了解品質限制後選用 ONNX。
- 模型驗證失敗：先確認資料夾與檔案來源；程式不會自動覆寫修改過的模型。
- 等待資源／RAM 預算不足：減少同時進行的其他工作，或在保留系統需求的前提下調整預算。
- 表格看起來錯誤：核對原頁與品質提醒，必要時保留原文處理；不能只靠表格外觀判定數字正確。
- 文字有誤但沒有高風險提醒：任何 OCR 都可能出錯。可使用雙引擎核對，重要數字、否定詞與正式對外文件仍需人工確認。

一般轉換在本機處理，未配置外部 AI 服務。模型下載會連線官方來源，使用者檔案不會作為模型下載內容上傳。第三方函式庫本身的行為仍以其文件與設定為準。

「說明」選單可開啟本手冊與第三方授權清單。完整授權文字及來源在隨附 licenses 資料夾；不要在轉發程式時刪除。授權清單不等於 Windows 最終二進位檔已完成發佈審核。
