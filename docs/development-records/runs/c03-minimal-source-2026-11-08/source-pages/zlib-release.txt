        <div data-pjax="true" data-test-selector="body-content" data-view-component="true" class="markdown-body tmp-my-3"><h1>zlib 1.4 Release Notes</h1>
<p><em>November 4, 2026</em></p>
<h2><strong>Changes in 1.4 (since 1.3.2)</strong></h2>
<h3>Breaking changes</h3>
<ul>
<li><strong>CMake:</strong>
<ul>
<li>The minimum CMake version is now 3.15, up from 3.12.</li>
<li>Library file names changed on MSVC: <code>z</code> is now <code>libz</code>, as in <code>libz.dll</code>, <code>libz.lib</code>, and the static <code>libzs.lib</code>. minizip's libraries changed the same way.</li>
<li>On Cygwin, the libraries now use the <code>lib</code> prefix.</li>
<li>Contrib targets and tests built as part of zlib are now prefixed with <code>zlib_</code>. Several test targets were renamed to one scheme, for example <code>zlib_examplestatic</code> and <code>minigzipstatic</code>.</li>
<li>The zlib1.dll option <code>ENABLE_BZIP2</code> is now <code>ZLIB1_DLL_ENABLE_BZIP2</code>.</li>
</ul>
</li>
<li>When not otherwise determined, <code>z_off_t</code> is again <code>long</code>, as in 1.3.1, instead of 1.3.2's <code>long long</code>. Windows applications built with 1.3.2 headers should be recompiled; see Enhancements for 64-bit offsets.</li>
<li><code>deflateReset()</code> now resets the gzip header set by <code>deflateSetHeader()</code>, as zlib.h has always said. Code relying on the header persisting must set it again.</li>
<li>Raw deflate that completes exactly at the end of the output buffer now returns <code>Z_STREAM_END</code> instead of <code>Z_OK</code>, as documented.</li>
<li><code>gzopen()</code> with <code>"x"</code> now fails where <code>O_EXCL</code> isn't available, instead of truncating an existing file (Trail of Bits TOB-ZLIB-009).</li>
<li>gzip reading now delivers the data decompressed before a read error, and only then reports the error.</li>
</ul>
<h3>Security fixes</h3>
<ul>
<li>Non-blocking <code>gzwrite()</code> had a buffer overflow; <a title="CVE-2026-85091" data-hovercard-type="advisory" data-hovercard-url="/advisories/GHSA-g5fp-32jq-cfw2/hovercard" href="https://github.com/advisories/GHSA-g5fp-32jq-cfw2">CVE-2026-85091</a> (reported by mat-mo; also TOB-ZLIB-003).</li>
<li><code>inflateGetDictionary()</code> could write up to 8 MB past the caller's 32K buffer (Theorem THM-ZLIB-001). This took a zlib header with an invalid window size, then <code>inflateReset()</code> or <code>inflateSync()</code>. Affects 1.3.1 and 1.3.2.</li>
<li><code>inflateSync()</code> before the window size was known allocated a one-byte window that could later be overrun (TOB-ZLIB-004).</li>
<li><code>inflatePrime()</code> could lead <code>inflate()</code> to read before the start of the input (TOB-ZLIB-014).</li>
<li>Repeated <code>deflatePrime()</code> calls could write past the pending buffer (TOB-ZLIB-013).</li>
<li><code>inflateBack()</code> failed to detect distances too far back, and copied uninitialized memory to the output (reported by Kornel Lesiński).</li>
<li><code>gzseek()</code> forward before any data was written could write uninitialized memory to the gzip output (found by Claude Opus 5.5).</li>
<li><code>deflateResetKeep()</code> used mid-stream could read outside the window (reported by Jason Gross).</li>
<li><code>gzdopen()</code> now sets close-on-exec with the correct flag (TOB-ZLIB-008).</li>
<li><strong>minizip:</strong>
<ul>
<li>A double free in <code>block_central_name()</code> (reported by Oculytic), and a NULL dereference on repeated <code>zipAlreadyThere()</code> calls after a bad central directory (reported by Naveed Khan).</li>
<li>Validation of extra-field sizes, plus portable, alignment-safe reading, in <code>zipRemoveExtraInfoBlock()</code> (reported by Naveed Khan and jmestwa-coder).</li>
<li>unzip no longer reads Zip64 values from outside their extra-field record (reported by Mohamed Elnady). It also uses only the Zip64 locator immediately before the end of central directory record (reported by snajafov). Crafted archives could make minizip report different entries than other readers.</li>
<li>miniunz could create directories outside the extraction directory (reported by Naveed Khan), and on Windows write files anywhere (reported by Trail of Bits). Fixed by Naveed Khan. Path names are now processed by component.</li>
</ul>
</li>
<li>contrib/infback9: removed out-of-bounds pointer arithmetic in inftree9.c; <a title="CVE-2026-4738" data-hovercard-type="advisory" data-hovercard-url="/advisories/GHSA-hp6p-5qh5-w9fj/hovercard" href="https://github.com/advisories/GHSA-hp6p-5qh5-w9fj">CVE-2026-4738</a> (fix by npt-1707, submitted by CrossVR). The pointers return in bounds before use and no known compiler mishandles this, so the critical rating overstates it, though it could trap on capability hardware such as CHERI.</li>
</ul>
<h3>Bug fixes</h3>
<ul>
<li><strong>gzip reading:</strong>
<ul>
<li>Restored the detection of truncated gzip streams, part of which was lost in 1.3.2. Also fixed a complete stream being reported as truncated.</li>
<li>An error in the first member is no longer treated as trailing garbage.</li>
<li>Corrected pending-skip handling in <code>gz_skip()</code>, <code>gzdirect()</code> and forced seeks at EOF.</li>
<li><code>gzgets()</code> now returns an empty string when promised.</li>
</ul>
</li>
<li><strong>gzip writing:</strong>
<ul>
<li>Successive <code>SEEK_CUR</code> seeks no longer lose zero fill.</li>
<li>Zero fill is now handled correctly after a write error.</li>
<li><code>gzprintf()</code> is now all-or-nothing when blocked, and is no longer a stub when compiled as C++.</li>
<li><code>gzseek()</code> leaves the position unchanged on failure.</li>
<li><code>gzopen_w()</code> now works with paths not representable in the locale.</li>
</ul>
</li>
<li><strong>inflate:</strong>
<ul>
<li><code>total_in</code> was short six bytes on <code>Z_NEED_DICT</code>.</li>
<li><code>inflateReset()</code> now restores the requested window size, and the wrap after <code>inflateSync()</code>.</li>
<li><code>inflateSetDictionary()</code> rejects a null dictionary.</li>
<li>With <code>PKZIP_BUG_WORKAROUND</code>, the code tables were slightly too small.</li>
</ul>
</li>
<li><strong>deflate:</strong>
<ul>
<li>A bad <code>deflateSetDictionary()</code> call is now detected as promised.</li>
<li>A failed <code>deflateCopy()</code> or <code>inflateCopy()</code> leaves the destination safe to end.</li>
<li>Removed a possible overflow in <code>deflate_stored()</code> comparisons.</li>
</ul>
</li>
<li>Undefined behavior removed in gzwrite.c, gzseek, <code>gz_vacate()</code> and mztools.c.</li>
<li><strong>minizip:</strong>
<ul>
<li>zip.c no longer writes corrupt headers when a Zip64 field overflows an extra field (reported by mzfr and itsgaldoron), or for Zip64 entries with file comments.</li>
<li><code>zipOpen3()</code> no longer leaks memory or returns a freed comment pointer on failure.</li>
<li>Added allocation checks.</li>
</ul>
</li>
<li><strong>Build:</strong>
<ul>
<li><code>configure</code> now builds the shared library with linkers such as lld that reject undefined symbols in zlib.map, including for <code>--solo</code>.</li>
<li>zlib.h no longer depends on <code>NULL</code> being defined.</li>
<li>zip.c builds with <code>NO_ADDFILEINEXISTINGZIP</code>.</li>
<li>The test programs use the generated zconf.h when building out of tree.</li>
</ul>
</li>
<li>Many CMake fixes: pkg-config files, installation of headers and of minizip's configuration, symbol prefixing, assembler detection, and parallel testing. It also works with CMake 4.</li>
</ul>
<h3>Enhancements</h3>
<ul>
<li>64-bit offsets on Windows with MSVC or MinGW, by compiling the application with <code>_FILE_OFFSET_BITS=64</code> or <code>_LARGEFILE64_SOURCE</code>. The library itself needs no changes.</li>
<li><strong>Platforms:</strong>
<ul>
<li>Android large file support.</li>
<li>An export list on AIX.</li>
<li><code>-Wno-psabi</code>, only where the PowerPC note would appear.</li>
<li>s390x <code>VGFMAFLAG</code> in configure.</li>
<li>Win32 Makefile.msc builds for ARM64.</li>
<li>minigzip's mmap code uses POSIX types.</li>
</ul>
</li>
<li><strong>CMake:</strong>
<ul>
<li>Package components, with <code>_FOUND</code> variables.</li>
<li>Installation and export of zlib1.dll and zlibwapi.dll.</li>
<li>Contribs build standalone, with zlib's defaults.</li>
<li>Tests consolidated, and tests on Windows.</li>
</ul>
</li>
<li><strong>minizip:</strong>
<ul>
<li>The traditional encryption header uses a PCG generator instead of <code>rand()</code>.</li>
<li>Fewer compiler warnings.</li>
</ul>
</li>
<li><strong>Documentation:</strong>
<ul>
<li>Clarified that undocumented functions are not part of the API.</li>
<li><code>inflateGetHeader()</code> header reuse.</li>
<li><code>deflateBound()</code> and <code>deflateSetDictionary()</code> ordering.</li>
<li>The application's responsibilities in unzip.h.</li>
</ul>
</li>
</ul>
<h3>Known issues</h3>
<ul>
<li>contrib/iostream2 is unsafe on untrusted input (reported by Trail of Bits). When reading a string, it uses the length stored in the compressed data without checking it, so a crafted file can write past the end of the destination buffer. Use contrib/iostream3 instead.</li>
</ul></div>
